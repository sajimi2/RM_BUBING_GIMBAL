# BT24 无线观察视觉 yaw（安卓手机 / VOFA+）

当前默认使用 **安卓手机已有的蓝牙助手**。用户以前已用该手机接收过 BT24 数据，
直接沿用原来的连接方法，无需新增软件、第二块 BT24 或 USB 转 TTL。
`VISION_TELEMETRY_ENABLED=1`，`VISION_TELEMETRY_FORMAT=VISION_TELEMETRY_TEXT`。

## 当前方案：一块 BT24 连接安卓手机

链路：C 板串口 → BT24 → 手机蓝牙助手。

1. 接 C 板外壳丝印 **UART1 三针接口**（软件 USART6）：
   **TX / PG14 → BT24 RX，GND → GND**，BT24 的 **VCC 另接稳压 5V**。
   三针口只有 GND、TX、RX，没有供电脚；外部电源 GND 必须与 C 板 GND 共地。
   这里的 5V 仅适用于用户确认 VCC 为 3.6–6V 的转接小板。
   只接收板端诊断数据时，BT24 TX 可不接；针号和方向见下文 C 板接线表。
2. 执行 VS Code 任务 **STM32Cube: 构建并烧录 Debug**。
   旧固件不会自动有新输出；完成下载并运行后可断开 ST-Link。
3. 手机沿用之前的方法连接 BT24，接收显示选择 **文本 / ASCII**，关闭 HEX 显示。
   C 板 USART6 当前为 **9600、8N1**，必须匹配 BT24 的实际 UART 波特率。
   手机 BLE 连接通常没有 UART 波特率设置；手机上选择波特率不等于修改模块串口。
4. 正常每 500 ms 显示一行。先发送固定 `+3 rad`，再固定 `-3 rad`，各保持数秒，
   保存两段完整文本。需要视觉控制实际生效时，`auto=1`、`rc=1`。

示例（仅示意字段，不是实测结果）：

```text
seq=10 ms=5000 raw=31290 used=31290 target=+3.000 fb=+0.250 err=+2.750 out=30000 auto=1 rc=1 rx=100 apply=100 pos=31290 neg=0 pc=100 nc=0 bus=2
```

| 字段 | 含义 |
| --- | --- |
| `seq` / `ms` | 板端开始发送的序号 / 开机毫秒数 |
| `raw` / `used` | 最近收到 / 最近实际采用的 yaw 原始有符号整数 |
| `target` / `fb` / `err` | 目标角 / 反馈角 / 环绕误差，均为 **rad**，显示三位小数 |
| `out` | Yaw 电机指令原始值，不是伏特 |
| `auto` / `rc` | 视觉控制生效 / 遥控器在线，0 或 1 |
| `rx` / `apply` | 累计收到 / 采用的有效视觉帧数 |
| `pos` / `neg` | 最近收到的正 / 负原始值，换符号后仍保留 |
| `pc` / `nc` | 累计收到的正 / 负帧数 |
| `bus` | 接收 CAN 总线，1 或 2 |

发送 `±3 rad` 时，`raw` 和 `used` 应约为 `±31290`，`target` 应为 `±3.000`。
文本四舍五入到 0.001 rad，只影响显示精度，不改变 PID 计算或控制目标。
`invalid` 表示非有限值或超出文本格式的 ±10000 rad 范围，需要检查数据来源。

`seq` 跳号说明已开始发送的数据没有完整出现在日志中，可能在串口、蓝牙或手机接收环节缺失；
不能只据此断言是无线丢包。若序号连续但 `ms` 间隔明显增大，可能是发送忙或任务延后。
序号和毫秒数都是 uint32，长时间运行会回绕。2 Hz 适合看目标和稳定结果，不能捕获全部控制瞬态。
接收与控制字段更新时刻不同，分析固定目标稳定后的值。

## 可选方案：电脑 VOFA+

使用下列电脑方案前，将 `VISION_TELEMETRY_FORMAT` 改成
`VISION_TELEMETRY_JUSTFLOAT`，重新构建烧录。该格式是 16 通道二进制，10 Hz；
手机文本模式不应按 JustFloat 解析。

链路：C 板 → BT24 从机 → 无线 → BT24 主机 → USB 转 TTL → 电脑 VOFA+。
烧录后无需保持 ST-Link 连接；VOFA 选择 USB 转 TTL 生成的 COM 口。

当前已完成板端输出及离线验证，尚未验证本工程到手机的实际接收，也未验证两块 BT24 的主从互连。
只有 `BT24` 标识不能确认角色。两块若都只有从机固件，不能直接互连，
需要其中一块具备厂家主机固件。主从角色与数据传输方向不同，从机也能发送观测数据。

## 先用 USB 转 TTL 识别模块

两块依次接电脑，配置期间先不接 C 板，另一块暂不上电。
以下供电适用于用户已确认 **VCC 3.6–6 V 的四针转接小板**，
不能套用到 3.3 V 供电的 BT24 裸模块。

| USB 转 TTL | BT24 小板 |
| --- | --- |
| 5V 电源 | VCC |
| GND | GND |
| TXD（3.3 V 逻辑） | RX |
| RXD | TX |

供电 5 V 与 TX/RX 的信号电平是两件事；确认 USB 转 TTL 的 TXD 为 3.3 V 逻辑。
不要把模块接到 RS232 电平接口。

在串口文本收发界面选择对应 COM，先用厂家默认 **9600、8N1、无流控**，
按 ASCII 文本逐条发送，每条结尾加 **CRLF（十六进制 0D 0A）**：

```text
AT
AT+VERSION
AT+BAUD
AT+LADDR
```

`AT` 正常返回 `OK`；记录两块各自的版本、波特率与地址。
`AT+BAUD` 返回 `3` 表示 9600。若曾改过波特率，应先使用模块当前波特率；
完全无回应不能直接判断模块损坏或只有从机功能。
这里读取的是文本响应，先不要用 JustFloat 引擎解释 AT 返回内容。

厂家主机手册还提供 `AT+INQ` 搜索命令。未建立蓝牙连接时发送该命令：

- 若返回 `+INQS`、`+INQ:...`、`+INQE` 等扫描结果，可确认该固件支持主机搜索。
- 若 `AT` 能返回 `OK` 而 `AT+INQ` 不支持，保留版本和完整响应，再向卖家核对固件。
  不能仅凭没有搜到设备判定是从机。

确认一主一从后，给从机上电，在接电脑的主机端发送 `AT+INQ`，
按之前记录的 MAC 地址找到自己的从机。例如本次扫描序号为 `2`，发送 `AT+CONN2`。
收到 `+Connected>>...` 后进入透传。具体序号随每次扫描变化，不要盲用示例值。
需要上电自动回连时，厂家主机固件支持 `AT+BIND` 加从机的 12 位 MAC 地址；
在未连接的命令模式下设置。确认型号和固件匹配后再设置，不套用 HC-05 的 `AT+ROLE`。

以上指令依据厂家 [BT24 从机应用指导](https://www.szdx-smart.com/static/upload/2025/10/23/202510234819.pdf)
第 12–17 页及 [BT24 主机应用指导](https://www.szdx-smart.com/static/upload/2025/10/23/202510233006.pdf)
第 5、13–18 页。不同定制固件应以卖家随附说明为准。

## C 板接线

使用外壳丝印 **UART1 的三针接口**，软件对应 **USART6**。
DJI 手册按 MCU 名称称其为 UART6，外壳名称与软件名称不同。

| C 板接口针号 / 信号 | 接 BT24 从机 |
| --- | --- |
| 1：GND | GND |
| 2：TXD / PG14 | RX |
| 3：RXD / PG9 | TX（本次只发送观测数据，可不接） |
| 另接稳压 +5V | VCC（限上述 3.6–6 V 小板） |

三针线只能连接串口信号和地，不能仅靠它给 BT24 供电。不要把 RX 当成电源脚。
另取板上确认的 5V 输出，或使用与 C 板共地的独立 5V 电源。

针号应对照实际连接器方向，不能按表格直接理解为从左到右。
依据 [DJI C 型开发板用户手册](https://rm-static.djicdn.com/tem/35228/RoboMaster%20%20%E5%BC%80%E5%8F%91%E6%9D%BF%20C%20%E5%9E%8B%E7%94%A8%E6%88%B7%E6%89%8B%E5%86%8C.pdf)
的 UART 引脚表及接口位置图。电脑端主机继续按上表接 USB 转 TTL。

## 烧录与 VOFA 设置

1. VS Code → 终端 → 运行任务 → **STM32Cube: 构建并烧录 Debug**。
   这是下载并复位运行；仅 Ctrl+Shift+B 只构建。烧录后可断开 ST-Link。
2. 两模块建立透传连接；关闭占用 COM 的其他串口工具。
3. VOFA 选择 USB 转 TTL 的 COM，**9600、8 数据位、无校验、1 停止位、无流控**。
   本方案两块 BT24 都使用 9600；若模块参数不同，先按其说明统一。
4. 数据引擎选择 **JustFloat**，打开串口。输出为 16 通道，每 100 ms 一帧。
   波形时间间隔 Δt 设为 **100 ms**；实际无线丢帧时，用通道 15 的板端时间判断间隔。
5. 保存或导出带全部通道的 CSV，并记录本次固件和视觉目标设置。

没有数据时，先观察 USB 转 TTL 是否收到字节，再检查 JustFloat 解析。
如需单独确认板端，可在云台静止时暂用 C 板 TX → USB 转 TTL RX、GND → GND 直连；
C 板独立供电，不再连接 USB 转 TTL 的电源到 C 板。

## 通道表（从 0 开始）

| 通道 | 建议名称 | 含义 / 单位 |
| --- | --- | --- |
| 0 | 收到的 yaw 原始值 | CAN 解码后的有符号整数 |
| 1 | 采用的 yaw 原始值 | 云台任务最近采用的有符号整数 |
| 2 | yaw 目标（rad） | 当前实际位置环目标 |
| 3 | yaw 反馈（rad） | 当前 INS 角度 |
| 4 | yaw 误差（rad） | 位置环环绕后的误差 |
| 5 | yaw 电机指令（原始值） | 控制器给定值，不是伏特或角度 |
| 6 | 视觉控制生效 | 0 / 1 |
| 7 | 遥控器在线 | 0 / 1 |
| 8 | 视觉接收帧数 | 累计有效帧数 |
| 9 | 视觉采用帧数 | 累计采用帧数 |
| 10 | 最近正 yaw 原始值 | 保留最近正值 |
| 11 | 最近负 yaw 原始值 | 保留最近负值 |
| 12 | 正 yaw 接收帧数 | 累计正值帧数 |
| 13 | 负 yaw 接收帧数 | 累计负值帧数 |
| 14 | 接收 CAN 总线 | 1 / 2；未收到时为 0 |
| 15 | 板端时间（s） | 开机后 HAL 时钟，约 49.7 天回绕 |

先将通道 2、3、4 放在同一幅图中，显示增益都设为 1。
把通道 0、1 放另一幅图；原始整数与 rad 混用同一纵轴会压扁角度曲线。
通道 6、7 在视觉闭环测试时都应为 1。

发送固定正目标、固定负目标，各保持数秒并记录曲线。
正确缩放的 `+3 rad` / `-3 rad` 对应原始值约 `+31290` / `-31290`，
通道 2 应分别接近 `+3` / `-3`。按照“收到 → 采用 → 实际目标 → 反馈/输出”
定位差异，不能只用肉眼转向判断是哪一层丢失符号。

10 Hz 用于观察目标是否采用及最终朝向，不能捕获所有 2 ms 控制瞬态。
接收和控制字段来自不同更新时刻，使用固定目标稳定后的数据分析。
计数作为 float32 传输，超过 16777216 后不能逐帧精确显示。

## 实现与验证范围

`Debug/vision_telemetry.c` 从 `vision_debug` 读取快照，由原 `test_task` 调用。
USART6 使用现有 DMA2 Stream6，发送忙时跳过，不等待串口完成。
默认文本使用 256 字节静态缓冲区、CRLF 行尾、2 Hz，最大串口占用低于 512 字节/秒。
可选 JustFloat 帧为 16 个小端 float32 加 `00 00 80 7F`，共 68 字节，10 Hz 为 680 字节/秒。
USART6 当前专用于诊断；旧 `usart6_debug.c` 的输出函数目前无任务调用，
后续不要同时向该串口写入其他 printf 内容。原四针口 USART1 恢复为 115200，不再发送本诊断数据。

`Debug/vision_telemetry.h` 的 `VISION_TELEMETRY_ENABLED` 设为 0 可停用输出。
CubeMX 配置已同步 USART6 波特率和 test 任务栈大小；重新生成后仍须保留任务中的调用。
本次遥测接入未改动视觉目标公式和 PID 参数。

已通过 CMake Debug / Release、Keil 构建，以及以下主机测试：

```powershell
rtk proxy python -X utf8 tools/check_vision_telemetry.py
```

测试执行真实遥测源文件，检查手机文本的正负角度、计数、无效角度标记及带宽；
也检查 JustFloat 帧、DMA 忙时缓冲区不被覆盖、中断状态恢复、计时回绕及关闭输出。
编译和主机测试不代表本工程数据已被手机收到、固件已下载或实车问题已解决。
